# Очереди (share groups, KIP-932) — экспериментально

Начиная с версии 1.10.0 компонента умеет читать топик **как очередь**: несколько читателей
одной группы получают разные записи одной партиции, а каждую запись читатель подтверждает
отдельно — «обработано», «вернуть в очередь» или «отклонить». Это реализация
[KIP-932 «Queues for Kafka»](https://cwiki.apache.org/confluence/display/KAFKA/KIP-932%3A+Queues+for+Kafka)
через share consumer библиотеки librdkafka 2.16.0.

> **Экспериментальная функция.** В librdkafka share consumer имеет статус Preview: API может
> измениться в следующих версиях библиотеки, а вместе с ним — методы компоненты. Не используйте
> очереди в продуктивных контурах до выхода стабильной версии.

## Чем очередь отличается от обычного чтения

| | Consumer group (`ИнициализироватьКонсьюмера`) | Очередь (`ИнициализироватьКонсьюмераОчереди`) |
|---|---|---|
| Кто читает партицию | Ровно один участник группы | Все участники группы одновременно |
| Параллельность | Не больше числа партиций | Не ограничена числом партиций |
| Порядок обработки | Сохраняется внутри партиции | Не гарантируется |
| Что фиксируется | Смещение партиции (всё до него прочитано) | Решение по каждой записи |
| Повтор при сбое | Перечитать с зафиксированного смещения | Запись возвращается в очередь сама |
| Счётчик доставок | Нет | `delivery_count` у каждой записи |
| Позиционирование (`ПерейтиКНачалу` и т.п.) | Есть | Нет |

**Когда подходит очередь:** независимые задания, которые можно обрабатывать в любом порядке
и параллельно больше, чем партиций в топике — рассылки, загрузка документов, обработка заявок,
задания для нескольких фоновых заданий 1С. Неудачную запись можно вернуть на повтор
(`release`) или отбросить (`reject`), не останавливая чтение остальных.

**Когда не подходит:** когда важен порядок (изменения одного объекта, журнал событий, CDC),
когда нужно перечитать топик с произвольной позиции, когда нужна семантика Exactly-Once
(транзакции компоненты работают только с обычным consumer).

## Требования и ограничения

- **Брокер Apache Kafka 4.2 или новее** с включёнными share groups (`share.version=1`;
  в 4.2 включено по умолчанию). На более старом брокере инициализация и подписка проходят
  успешно, а **первое чтение** возвращает пустую строку и ошибку вида
  `Fatal error: ShareGroupHeartbeat fatal error: Broker: API version not supported`.
- **Блокировка записи.** Прочитанная запись закреплена за читателем на
  `group.share.record.lock.duration.ms` (настройка брокера, по умолчанию **30 секунд**). Если
  за это время запись не подтверждена, брокер отдаёт её другому читателю. Продлить блокировку
  нельзя. Поэтому обработка должна укладываться в это время, а **повторная обработка одной
  записи должна быть безопасной** (идемпотентной): та же запись может прийти дважды.
- **Лимит доставок.** После `group.share.delivery.count.limit` доставок (по умолчанию 5)
  брокер перестаёт отдавать запись и архивирует её. Текущее число доставок — поле
  `delivery_count` в пакете.
- **Новая группа читает только новые сообщения.** Share group по умолчанию начинает с конца
  топика (`share.auto.offset.reset=latest`), записанные до её создания сообщения она не увидит.
  Это настройка группы на брокере, через `УстановитьПараметр` её не задать. Чтобы группа
  читала топик с начала, до первого подключения выполните на брокере:

  ```bash
  kafka-configs.sh --bootstrap-server localhost:9092 --entity-type groups \
    --entity-name my-queue-group --alter --add-config share.auto.offset.reset=earliest
  ```

- **Параллельность ограничена пакетами продюсера.** Брокер выдаёт читателям записи целыми
  пакетами (record batch), в которые их сложил продюсер. Если 100 сообщений отправлены одним
  пакетом, их получит один читатель, даже если читателей несколько. `max.poll.records`
  ограничивает число записей в выдаче, но пакет не дробит. Для равномерного распределения
  отправляйте задания небольшими пакетами (например, `ОтправитьСообщениеСОжиданиемРезультата`
  или уменьшенные `batch.num.messages` / `linger.ms` у продюсера).
- **Нет администрирования share groups** (список групп, отставание, удаление) — в librdkafka
  этих операций пока нет. Используйте `kafka-share-groups.sh` на стороне брокера.
- Подписка только по точным именам топиков, без регулярных выражений.
- Методы `ПолучитьДанныеСообщения` и другие получатели «текущего сообщения» к очереди не
  относятся: все данные записи — в JSON пакета. Avro и Protobuf декодируются существующими
  методами по полю `message` (используйте `КакBase64 = Истина`).

## Инициализация

```1c
ИнициализироватьКонсьюмераОчереди(Брокеры, ИмяГруппы)
```

**Брокеры** — Строка. Список брокеров, например `"kafka1:9092,kafka2:9092"`.

**ИмяГруппы** — Строка. Имя share group, обязательно.

Возвращает Булево.

Особенности:

1. Режим подтверждения всегда явный (`share.acknowledgement.mode=explicit`): каждую
   прочитанную запись нужно подтвердить. Значение этого параметра из `УстановитьПараметр`
   заменяется.
2. Применяются параметры из `УстановитьПараметр`, в том числе SSL/SASL и `openssl.*`.
   Параметры, которые имеют смысл только для обычного consumer и которые librdkafka для
   очереди отвергает, пропускаются с записью в лог `[share] ignored property <имя>`:
   `enable.auto.commit`, `auto.offset.reset`, `isolation.level`, `enable.partition.eof`,
   `partition.assignment.strategy`, `group.protocol`, `group.protocol.type`,
   `group.remote.assignor`, `group.instance.id`, `session.timeout.ms`,
   `heartbeat.interval.ms`, `socket.max.fails`, `queued.min.messages`,
   `queued.max.messages.kbytes`, `fetch.queue.backoff.ms`, `fetch.error.backoff.ms`,
   `message.copy.max.bytes`, `topic.blacklist`, `allow.auto.create.topics`,
   `consume.callback.max.messages`. Поэтому один объект компоненты с одними параметрами
   может работать и с обычным consumer, и с очередью одновременно.
3. `group.id` из `УстановитьПараметр` для очереди не используется — группа задаётся
   параметром `ИмяГруппы`.
4. Повторный вызов закрывает предыдущего читателя очереди (как `ОстановитьКонсьюмераОчереди`).
5. Лог пишется в лог консьюмера (`КаталогЛогов`) с префиксом `[share]`, включая сообщения
   librdkafka и версию библиотеки.

## Подписка

```1c
ПодписатьсяНаОчередь(Топики)
ОтписатьсяОтОчереди()
```

**Топики** — Строка, имена через запятую. Пустой список — ошибка `Topic list is empty`.
Повторный вызов заменяет подписку. Методы возвращают Булево.

Первые чтения после подписки могут вернуть пустой пакет: читатель входит в группу, это
занимает несколько секунд.

## Чтение пакета

```1c
ПрочитатьПакетИзОчереди(МаксОжиданиеМс, КакBase64, ВернутьНеподтвержденные)
```

**МаксОжиданиеМс** — Число. Сколько ждать записи, мс. По умолчанию 1000.

**КакBase64** — Булево. Возвращать тело сообщения в Base64. По умолчанию `Ложь`.

**ВернутьНеподтвержденные** — Булево. По умолчанию `Ложь`. См. ниже.

Возвращает Строку — JSON в формате [`ЧитатьПакетСообщений`](consumer.md#пакетное-чтение-сообщений),
в каждой записи дополнительно поле `delivery_count`:

```json
{
    "messages": [
        {
            "message": "{\"order\":42}",
            "key": "order-42",
            "topic": "orders",
            "partition": 0,
            "offset": 1500,
            "broker_id": 1,
            "timestamp": 1760000000000,
            "delivery_count": 1
        }
    ],
    "count": 1
}
```

Особенности:

1. Если за время ожидания записей нет — `{"messages":[],"count":0}`, это не ошибка.
2. Перед следующим чтением **все записи предыдущего пакета должны быть подтверждены**. Иначе:
   - при `ВернутьНеподтвержденные = Ложь` метод возвращает пустую строку и ошибку
     `Previous batch has unacknowledged records`, к брокеру не обращается;
   - при `ВернутьНеподтвержденные = Истина` всем неподтверждённым записям ставится `release`
     (они вернутся в очередь с увеличенным `delivery_count`), затем выполняется чтение.
     Это удобно после исключения в обработчике: не нужно перезапускать читателя.
3. Запись, которую librdkafka не смогла разобрать (битый пакет, ошибка распаковки), приходит
   с полем `error` и без данных; `topic`, `partition`, `offset` заполнены. Подтверждать её
   не нужно и нельзя — библиотека сама отклоняет её (`reject`) или возвращает (`release`).
4. Ошибка чтения — пустая строка, текст в `ПолучитьСообщениеОбОшибке()`. Ошибка с префиксом
   `Fatal error:` означает, что читатель неработоспособен — его нужно пересоздать.
5. Компонента держит последний пакет до следующего чтения или остановки — по нему
   подтверждаются записи.

## Подтверждение записи

```1c
ПодтвердитьСообщениеОчереди(Топик, Раздел, Смещение, Решение)
```

**Топик** — Строка.

**Раздел** — Число, номер партиции.

**Смещение** — Строка или Число. **Передавайте Строкой**: Число больше 2 147 483 647
платформа может обрезать при передаче во внешнюю компоненту. Из JSON пакета смещение
приходит Числом — преобразуйте его `Формат(Смещение, "ЧН=0; ЧГ=")`.

**Решение** — Строка, регистр не важен:
- `accept` — запись обработана, больше не доставляется;
- `release` — вернуть в очередь, её получит этот или другой читатель, `delivery_count` увеличится;
- `reject` — отклонить, больше не доставляется (например, неисправимо битые данные).

Возвращает Булево. Ошибки:

| Текст ошибки | Причина |
|---|---|
| `Record not found in current batch` | Записи нет в последнем прочитанном пакете |
| `Record is already acknowledged` | Решение по записи уже принято |
| `Record has error and is acknowledged automatically` | Запись с полем `error` |
| `Invalid acknowledgement type "...", expected accept, release or reject` | Неверное `Решение` |

Подтверждение только отмечает запись. Брокер получает его при следующем
`ПрочитатьПакетИзОчереди`, `ЗафиксироватьПодтвержденияОчереди` или `ОстановитьКонсьюмераОчереди`.

## Пакетное подтверждение

```1c
ПодтвердитьСообщенияОчереди(Подтверждения)
```

**Подтверждения** — Строка, JSON-массив:

```json
[
    {"topic": "orders", "partition": 0, "offset": "1500", "ack": "accept"},
    {"topic": "orders", "partition": 0, "offset": "1501", "ack": "release"}
]
```

`offset` — строка или число. Обрабатываются все элементы; если какие-то не прошли, метод
возвращает `Ложь`, а текст ошибки перечисляет их по индексу (с нуля):
`Failed to acknowledge 1 of 2 record(s): item 1: Record not found in current batch`.
Успешные элементы остаются подтверждёнными.

## Фиксация подтверждений

```1c
ЗафиксироватьПодтвержденияОчереди(ТаймаутМс)
```

**ТаймаутМс** — Число, по умолчанию 5000.

Синхронно отправляет накопленные подтверждения брокеру и ждёт ответа. Возвращает Булево.
Если брокер отклонил подтверждения по какой-то партиции — `Ложь` с текстом
`Share commit failed for <топик>[<партиция>]: <ошибка>`. Повтора нет: записи с
неподтверждёнными решениями вернутся в очередь по истечении блокировки. Если подтверждений
нет — `Истина`.

Вызывать необязательно: подтверждения уходят и со следующим чтением, и при остановке.
Нужен, когда важно убедиться, что решения дошли до брокера, до продолжения работы.

## Остановка

```1c
ОстановитьКонсьюмераОчереди()
```

Отправляет принятые решения, выходит из группы и освобождает читателя. Время ограничено
примерно `socket.timeout.ms`. Неподтверждённые записи вернутся в очередь по истечении
блокировки. Возвращает Булево. Повторный вызов безопасен. При уничтожении объекта
компоненты читатель останавливается автоматически.

## Пример: фоновое задание обработки очереди

Несколько экземпляров фонового задания с одной группой делят записи между собой. Запись,
которую не удалось обработать, возвращается на повтор, а после трёх неудачных доставок
отклоняется. Пример рассчитан на конфигурацию с БСП (`ОбщегоНазначения.КодОсновногоЯзыка()`
для имени события журнала регистрации, стандарт [#std498](https://v8std.ru/std/498/)).

```1c
Процедура ОбработатьОчередьЗаказов() Экспорт

	Компонента = Новый("AddIn.Integration.simpleKafka1C");
	Компонента.УстановитьКаталогЛогов(КаталогВременныхФайлов());

	Если Не Компонента.ИнициализироватьКонсьюмераОчереди("kafka1:9092", "orders-workers")
		Или Не Компонента.ПодписатьсяНаОчередь("orders") Тогда
		ВызватьИсключение Компонента.ПолучитьСообщениеОбОшибке();
	КонецЕсли;

	ИмяСобытия = НСтр("ru = 'Kafka.Очередь заказов'", ОбщегоНазначения.КодОсновногоЯзыка());
	МаксимумПопыток = 3;
	ОкончаниеРаботы = ТекущаяДатаСеанса() + 300;

	Попытка

		Пока ТекущаяДатаСеанса() < ОкончаниеРаботы Цикл

			// Истина: записи, оставшиеся неподтверждёнными после исключения, вернутся в очередь
			ТекстПакета = Компонента.ПрочитатьПакетИзОчереди(2000, Ложь, Истина);
			Если ТекстПакета = "" Тогда
				ВызватьИсключение Компонента.ПолучитьСообщениеОбОшибке();
			КонецЕсли;

			ЧтениеJSON = Новый ЧтениеJSON;
			ЧтениеJSON.УстановитьСтроку(ТекстПакета);
			Пакет = ПрочитатьJSON(ЧтениеJSON, Истина);
			ЧтениеJSON.Закрыть();

			Для Каждого Запись Из Пакет["messages"] Цикл

				Если Запись.Получить("error") <> Неопределено Тогда
					// Подтверждает сама библиотека
					ЗаписьЖурналаРегистрации(ИмяСобытия, УровеньЖурналаРегистрации.Ошибка, , ,
						Запись["error"]);
					Продолжить;
				КонецЕсли;

				Решение = "accept";
				Попытка
					ОбработатьЗаказ(Запись["message"]);
				Исключение
					ЗаписьЖурналаРегистрации(ИмяСобытия, УровеньЖурналаРегистрации.Ошибка, , ,
						ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
					Решение = ?(Запись["delivery_count"] >= МаксимумПопыток, "reject", "release");
				КонецПопытки;

				Если Не Компонента.ПодтвердитьСообщениеОчереди(Запись["topic"], Запись["partition"],
					Формат(Запись["offset"], "ЧН=0; ЧГ="), Решение) Тогда
					ВызватьИсключение Компонента.ПолучитьСообщениеОбОшибке();
				КонецЕсли;

			КонецЦикла;

		КонецЦикла;

	Исключение
		Компонента.ОстановитьКонсьюмераОчереди();
		ВызватьИсключение;
	КонецПопытки;

	Компонента.ОстановитьКонсьюмераОчереди();

КонецПроцедуры
```

`ОбработатьЗаказ` должна быть идемпотентной: при превышении 30-секундной блокировки или сбое
до подтверждения тот же заказ придёт ещё раз.

## Пример: пакетное подтверждение

Если записи обрабатываются вместе (например, в одной транзакции), решения удобнее отправить
одним вызовом.

```1c
Подтверждения = Новый Массив;
Для Каждого Запись Из Пакет["messages"] Цикл
	Если Запись.Получить("error") <> Неопределено Тогда
		Продолжить;
	КонецЕсли;
	Элемент = Новый Структура;
	Элемент.Вставить("topic", Запись["topic"]);
	Элемент.Вставить("partition", Запись["partition"]);
	Элемент.Вставить("offset", Формат(Запись["offset"], "ЧН=0; ЧГ="));
	Элемент.Вставить("ack", ?(ТранзакцияЗафиксирована, "accept", "release"));
	Подтверждения.Добавить(Элемент);
КонецЦикла;

ЗаписьJSON = Новый ЗаписьJSON;
ЗаписьJSON.УстановитьСтроку();
ЗаписатьJSON(ЗаписьJSON, Подтверждения);

Если Не Компонента.ПодтвердитьСообщенияОчереди(ЗаписьJSON.Закрыть()) Тогда
	ВызватьИсключение Компонента.ПолучитьСообщениеОбОшибке();
КонецЕсли;

// Убедиться, что решения дошли до брокера
Если Не Компонента.ЗафиксироватьПодтвержденияОчереди(10000) Тогда
	ВызватьИсключение Компонента.ПолучитьСообщениеОбОшибке();
КонецЕсли;
```
