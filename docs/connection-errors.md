# Ошибки подключения: SSL, аутентификация, авторизация

С версии 1.10.3 компонента одинаково обрабатывает неустранимые ошибки подключения во всех
методах: служебных (список топиков, метаданные, Admin API), продюсере, транзакциях, консьюмере,
фоновом чтении, очередях и Schema Registry.

## Что изменилось

Раньше ошибка SSL-рукопожатия или аутентификации не прерывала вызов. librdkafka получает её
в фоновом потоке через ~50 мс и затем бесконечно повторяет подключение, а метод компоненты ждал
до конца своего таймаута и возвращал общий текст `Local: Broker transport failure` или «нет
сообщений». Причина была видна только в логе.

Теперь:

- **Быстрый отказ.** Метод ждёт отрезками по 500 мс и после каждого проверяет, не пришла ли
  неустранимая ошибка. Если пришла, метод сразу возвращает значение ошибки своего типа
  (`Ложь`, `-1`, пустая строка — см. [обработку исключений](exceptionHandling.md)). Обычно это
  занимает 0,5 с вместо полного таймаута.
- **Понятный текст.** `ПолучитьСообщениеОбОшибке()` возвращает текст librdkafka и подсказку.
- **Ошибка запоминается.** Если продюсер, консьюмер или консьюмер очереди однажды получил
  неустранимую ошибку, следующие вызовы возвращают её сразу, без ожидания. Сбрасывается
  ошибка только повторной инициализацией (`ИнициализироватьПродюсера`,
  `ИнициализироватьКонсьюмера` и т. п.) — исправьте настройки и пересоздайте клиента.

## Какие ошибки считаются неустранимыми

| Ошибка librdkafka | Пример причины |
|---|---|
| `Local: SSL error` (`ERR__SSL`) | имя хоста не совпадает с сертификатом, неверный CA, нет сертификата клиента |
| `Local: Authentication failure`, `SASL_AUTHENTICATION_FAILED` | неверный логин или пароль SASL |
| `*_AUTHORIZATION_FAILED` | у учётной записи нет прав (ACL) |
| ошибки с признаком fatal | например, ошибка идемпотентного продюсера |

Временные ошибки — брокер недоступен, порт закрыт, не разрешается имя — **не** прерывают
ожидание: брокер может подняться. По таймауту к тексту ошибки добавляется последняя такая
ошибка, например `Local: Broker transport failure | 1/1 brokers are down`.

## Подсказки

| Ситуация | Подсказка |
|---|---|
| `certificate verify failed`, проверка имени хоста включена (по умолчанию) | имя хоста не совпадает с CN/SAN сертификата брокера или `ssl.ca.location` не подтверждает сертификат |
| `certificate verify failed` при `ssl.endpoint.identification.algorithm=none` | проверьте `ssl.ca.location` |
| ошибка ключа или сертификата клиента | проверьте `ssl.key.location`, `ssl.certificate.location`, `ssl.key.password` |
| SASL | проверьте `sasl.mechanism`, `sasl.username`, `sasl.password` |
| нет прав | проверьте ACL брокера |
| Schema Registry по HTTPS | имя хоста не совпадает с CN/SAN сертификата сервера или CA не входит в доверенные сертификаты системы |

librdkafka не отличает несовпадение имени хоста от неверного CA: в обоих случаях текст
`certificate verify failed`. Поэтому подсказка называет обе причины.

## Частый случай: сертификат брокера без SAN

Начиная с librdkafka 2.0 проверка имени хоста включена по умолчанию
(`ssl.endpoint.identification.algorithm=https`). Если сертификат брокера выпущен без
`subjectAltName` для имени, по которому к нему подключаются, рукопожатие не проходит, хотя
CA верный. Старые сборки kafkacat (librdkafka 1.x) имя хоста не проверяли, поэтому с теми же
сертификатами «работают».

Правильное решение — перевыпустить сертификат брокера с SAN:

```
subjectAltName = DNS:kafka.internal
```

Временный обход — отключить проверку имени хоста. **Это ослабляет защиту:** клиент примет
любой сертификат, подписанный этим CA.

```bsl
Компонента.УстановитьПараметр("security.protocol", "SSL");
Компонента.УстановитьПараметр("ssl.ca.location", "C:\certs\ca-cert");
Компонента.УстановитьПараметр("ssl.certificate.location", "C:\certs\client.crt");
Компонента.УстановитьПараметр("ssl.key.location", "C:\certs\client.key");
Компонента.УстановитьПараметр("ssl.endpoint.identification.algorithm", "none");
```

Проверьте и `advertised.listeners` брокера: если он анонсирует `localhost`, список топиков
получить удастся, а отправка и чтение пойдут на `localhost` клиента и не сработают.

## Примеры

### Список топиков

```bsl
Топики = Компонента.ПолучитьСписокТопиков("kafka.internal:9093", 10000);
Если ПустаяСтрока(Топики) Тогда
	// Через ~0,5 с, а не через 10 с:
	// ssl://kafka.internal:9093/bootstrap: SSL handshake failed: ... certificate verify failed ...
	// | Возможно, имя хоста kafka.internal не совпадает с CN/SAN сертификата брокера, ...
	ВызватьИсключение Компонента.ПолучитьСообщениеОбОшибке();
КонецЕсли;
```

### Продюсер: ошибка запоминается

```bsl
Если Не Компонента.ИнициализироватьПродюсера(Брокеры) Тогда
	ВызватьИсключение Компонента.ПолучитьСообщениеОбОшибке();
КонецЕсли;

Статус = Компонента.ОтправитьСообщениеСОжиданиемРезультата(Текст, "orders");
Если Статус <> 2 Тогда // 2 — Persisted
	Ошибка = Компонента.ПолучитьСообщениеОбОшибке();
	// При ошибке SSL следующие ОтправитьСообщение сразу вернут -1 с тем же текстом.
	// Исправьте настройки и вызовите ИнициализироватьПродюсера заново.
	Компонента.ОстановитьПродюсера();
	ВызватьИсключение Ошибка;
КонецЕсли;
```

### Фоновое чтение

При неустранимой ошибке фоновое чтение останавливается и присылает одно событие `Stopped`
с текстом ошибки и подсказкой (см. [фоновое чтение](consumer.md#фоновое-чтение-push-режим)):

```bsl
&НаКлиенте
Процедура ВнешнееСобытие(Источник, Событие, Данные)
	Если Источник = "SimpleKafka" И Событие = "Stopped" Тогда
		Сообщить("Фоновое чтение остановлено: " + Данные);
	КонецЕсли;
КонецПроцедуры
```

## Ограничения

- Методы, которые работают поверх уже созданного консьюмера, но не читают сообщения
  (`ПолучитьСмещенияТекущегоКонсьюмера`, `СброситьОфсетыГруппыКонсьюмеров`,
  `ПерейтиКВременнойМетке`), отказывают быстро, только если ошибка уже была замечена
  раньше — например, при `Слушать` или `ЧитатьПакетСообщений`. Иначе они ждут свой таймаут,
  как и прежде, но возвращают текст с причиной.
- У Schema Registry нет собственных настроек TLS: curl использует хранилище доверенных
  сертификатов системы. curl не повторяет подключение, поэтому ошибка и раньше возвращалась
  сразу; теперь к ней добавлены подробности и подсказка.
