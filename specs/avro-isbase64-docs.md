# Спецификация: документирование параметра `IsBase64` и строгая проверка паддинга base64

Статус: черновик, ожидает утверждения
Связанные изменения: PR #88 «AVRO: явный параметр IsBase64 у DecodeAvroMessage/GetAvroSchema» (смержен в `main`),
обсуждение #87 (автораспознавание base64 отклонено)

## 1. Проблема

PR #88 добавил в компоненту необязательный параметр `IsBase64`:

- `DecodeAvroMessage` / `ДекодироватьСообщениеAVRO` — 4-й параметр, по умолчанию `Ложь`;
- `GetAvroSchema` / `ПолучитьСхемуAVRO` — 2-й параметр, по умолчанию `Ложь`.

Изменение поставлено без сопроводительных материалов, из-за чего:

1. **`docs/avro.md` описывает устаревшие сигнатуры.** Строка 495 —
   `ДекодироватьСообщениеAVRO(ДанныеAVRO, ИмяСхемыJSON, ВозвращатьJSON)`, строка 623 —
   `ПолучитьСхемуAVRO(ДанныеAVRO)`. Прикладной разработчик 1С не может узнать о параметре из
   документации, а сценарий, ради которого он появился (1С маршалит `ДвоичныеДанные` в нативный
   метод как base64-текст), нигде не описан — при столкновении с ним искать решение негде.
2. **Изменение не отражено в `CHANGELOG.md`.** Релиза 1.9.3 ещё не было, поэтому версия
   компоненты остаётся `1.9.3` (`src/SimpleKafka1C.h:31`), а запись добавляется в уже
   существующий раздел `## [1.9.3]`.
3. **`tryBase64Decode` не проверяет паддинг, хотя комментарий в `src/utils.h` это обещает.**
   Цикл разбора прерывается на первом символе `=` (`src/utils.cpp`), поэтому вход вида
   `QUJD=REVG` считается валидным base64 и молча декодируется как `ABC` — хвост после `=`
   отбрасывается без ошибки. Для флага, чей смысл — «при невалидном base64 дать явную ошибку,
   а не тихий фолбэк», это прямое нарушение контракта: часть данных теряется беззвучно.

## 2. Область изменений

В объём входит:

- `docs/avro.md` — актуализация двух разделов;
- `CHANGELOG.md` — запись в существующий раздел `## [1.9.3]`;
- `src/utils.cpp` / `src/utils.h` — строгая проверка паддинга в `tryBase64Decode`.

В объём **не** входит: смена версии компоненты (релиза 1.9.3 не было), сборка и упаковка релиза,
изменение сигнатур, поведения по умолчанию, добавление автораспознавания base64 (отклонено в #87),
правки PR #81.

## 3. Требования

### R1. Документация метода `ДекодироватьСообщениеAVRO`

Сигнатура в `docs/avro.md` приведена к фактической, добавлено описание параметра `IsBase64`:
тип Булево, необязательный, по умолчанию `Ложь`; `Ложь` — байты берутся как есть (прежнее
поведение); `Истина` — вход сначала декодируется из base64, и если он не является валидным
base64, метод возвращает пустую строку с ошибкой в `ПолучитьСообщениеОбОшибке()`.

### R2. Документация метода `ПолучитьСхемуAVRO`

То же для второго параметра.

### R3. Раздел о причине появления параметра

В `docs/avro.md` добавлено объяснение, когда `IsBase64 = Истина` вообще нужен: 1С в ряде случаев
передаёт `ДвоичныеДанные` в нативный метод как base64-текст. Явно указано, почему параметр
обязан задаваться вызывающим, а не определяться автоматически: сырой Avro-payload может целиком
состоять из символов алфавита base64, поэтому угадывание небезопасно.

### R4. Примеры на языке 1С

Каждый из двух разделов содержит рабочий пример вызова с `IsBase64 = Истина`, включая обработку
ошибки через `ПолучитьСообщениеОбОшибке()`. Существующие примеры без параметра сохранены —
они демонстрируют, что старый код менять не требуется.

### R5. Строгая проверка паддинга

`tryBase64Decode` возвращает `false`, если:

- после первого `=` во входе встречается любой символ, кроме `=` и пробельных;
- символов `=` больше двух;
- паддинг присутствует, но не дополняет группу до кратной четырём: `(k + число '=') % 4 != 0`,
  где `k` — количество значащих символов. Отсюда при `k % 4 == 0` паддинг запрещён,
  при `k % 4 == 3` допустим ровно один `=`, при `k % 4 == 2` — ровно два;
- `k == 0` или `k % 4 == 1` (уже реализовано, сохраняется).

Вход без паддинга остаётся допустимым при любом `k`, кроме `k % 4 == 1`.

Толерантность к пробельным символам и переносам строк, к обоим алфавитам (`+/` и URL-safe `-_`)
и к отсутствию паддинга сохраняется.

### R6. Согласованность комментария

Комментарий к `tryBase64Decode` в `src/utils.h` соответствует фактическому поведению.

### R7. Журнал изменений

В `CHANGELOG.md`, в существующий раздел `## [1.9.3]`, добавлено описание параметра `IsBase64`
и ужесточения проверки паддинга. Константа `Version` не меняется.

## 4. Критерии приёмки

**AC1 — обратная совместимость документации**
Дано: код 1С, вызывающий `ДекодироватьСообщениеAVRO(Данные, "User", Истина)` без четвёртого
параметра.
Когда: разработчик сверяется с обновлённым `docs/avro.md`.
Тогда: документация подтверждает, что вызов остаётся корректным, а поведение — прежним.

**AC2 — сценарий base64 описан**
Дано: разработчик получил ошибку декодирования, потому что 1С передала `ДвоичныеДанные`
как base64-текст.
Когда: он открывает раздел «Декодирование AVRO сообщения».
Тогда: он находит описание этого сценария, параметр `IsBase64`, пример вызова и объяснение,
почему параметр не определяется автоматически.

**AC3 — обрыв на `=` больше не проходит молча**
Дано: вход `QUJD=REVG` и `IsBase64 = Истина`.
Когда: вызывается `ДекодироватьСообщениеAVRO`.
Тогда: метод возвращает пустую строку, `ПолучитьСообщениеОбОшибке()` сообщает о невалидном
base64. До изменения вход декодировался как `ABC` без каких-либо признаков потери данных.

**AC4 — корректный base64 по-прежнему принимается**
Дано: входы `QUJD` (без паддинга), `QUJDRA==` (два `=`), `QUJDRAU=` (один `=`), а также те же
значения с переносами строк и в URL-safe алфавите.
Когда: вызывается `tryBase64Decode`.
Тогда: все декодируются успешно и байт в байт совпадают с результатом до изменения.

**AC5 — Confluent-заголовок остаётся ошибкой**
Дано: сырой payload, начинающийся с `0x00`, и `IsBase64 = Истина`.
Когда: вызывается `ДекодироватьСообщениеAVRO`.
Тогда: метод возвращает пустую строку с явной ошибкой, без фолбэка на сырые байты.

**AC6 — рассогласованный паддинг отвергается**
Дано: входы `QUJDRA=` (`k % 4 == 2`, один `=`) и `QUJD=` (`k % 4 == 0`, паддинг при полной группе).
Когда: вызывается `tryBase64Decode`.
Тогда: обе строки отвергаются с `false`.

**AC7 — проверка без релизной сборки**
Дано: изменённый `tryBase64Decode`.
Когда: логика проверяется автономной программой, собранной из копии функции.
Тогда: все случаи AC3–AC6 дают ожидаемый результат. Релизная сборка компоненты и упаковка
макета в объём не входят.
